  ---
  Summary

  The plan covers the full Linux TEE backend implementation:

  Core design decisions

  Same enclave.Key interface — zero changes to the macOS SE path or the gateway
  contract. The internal/tee/ package is a parallel implementation with
  build-tag-gated backends: //go:build linux && cgo && tdx|snp|nitro, plus an
  attest_stub.go (!tdx && !snp && !nitro) that compiles everywhere for dev and
  CI.

  Attestation binding — user_data = SHA256(pubkey || modelHash). This is the
  cryptographic tie that lets a client verify: this key lives in real TEE 
  hardware AND it's serving this exact model. Both facts are hardware-signed.

  No hardware required to develop — the stub backend plus CoCo's
  kata-qemu-coco-dev runtime class give you two layers of software-only
  development before needing real TDX/SNP iron.

  k3d can't work — Docker's nested virt intercepts TDCALL/SNP_GET_REPORT.
  Bare-metal k3s + CoCo operator is the only path. The plan documents exactly
  why and what the install flow looks like.
